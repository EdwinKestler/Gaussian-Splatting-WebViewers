One continuous workflow

Render a scene. Discover its structure. Make it yours.

The core path stays client-side. Web Workers handle the expensive graph and meshing stages while WebGPU handles sorting, rasterization, contribution tracking, picking, and readback.

01

Decode & render

Load six Gaussian formats through vendored GaussForge, preserve float covariance and SH, then render paper-style EWA ellipses with a GPU counting sort.

02

Segment & understand

Build kNN superpoints, lift 2D masks into Gaussian labels with α·T contributions, name instances, and search them with optional CLIP embeddings.

03

Edit & deliver

Select, transform, duplicate, hide, merge, and rename objects with a replayable operation log. Export PLY, SPLAT, SPZ, compressed PLY, or a GLB mesh.

F0–F6 architecture

A traceable object pipeline.

Every stage has a concrete browser module, deterministic test fixtures, and exportable artifacts.

  1. Decode into 12-float Gaussians plus SH coefficients.
  2. Rasterize color, depth, normal, ID, and contribution buffers.
  3. Group Gaussians into graph-based superpoints.
  4. Lift masks across views into persistent 3D instances.
  5. Name and edit with undoable, replayable operations.
  6. Export or mesh the selected object or visible scene.

Before you launch

Static by design. Local when it matters.

Browser requirements

  • A recent Chrome or Edge release with WebGPU enabled.
  • The included 8 MB compact scene loads automatically.
  • Drop your own trained point_cloud.ply for full SH3 rendering.
  • SAM 2.1 and CLIP may download weights from their public providers.

Optional local sidecar

Grok vision, instance naming, Imagine cards, and saving artifacts require the loopback Python sidecar. It is never deployed to GitHub Pages, and your XAI_API_KEY never reaches this site.
